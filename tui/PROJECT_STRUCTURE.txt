Key Dependencies
================
ratatui 0.30            - TUI framework (panels, widgets, layout)
ratatui-image 10.0      - Image rendering (Kitty protocol)
crossterm 0.29          - Terminal control (raw mode, events)
tui-tree-widget 0.22    - Tree view widget (for future tree expansion)
tokio 1.x               - Async runtime (image loading, non-blocking)
image 0.25              - Image decoding (PNG, JPEG, etc.)
serde 1.x               - Serialization framework
serde_json 1.x          - JSON parsing (catalog loading)
lru 0.12                - LRU cache (image caching)
anyhow 1.x              - Error handling
chrono 0.4              - Timestamp handling (audit log)

State Flow
==========
1. User Input (keyboard) -> main.rs event loop
2. Event dispatched based on app.focus
3. App state updated (app.rs methods)
4. UI re-rendered (ui/mod.rs -> individual panels)
5. Terminal updated via ratatui


Performance Characteristics
===========================
Startup Time:        ~200ms (catalog load + first image)
Grid Navigation:     <16ms (cached images)
Search:              ~10ms (4,205 icons, O(n) scan)
Memory Usage:        ~200MB (200 cached images)
Image Load (async):  20-50ms per image
Binary Size:         3.7MB (release, stripped)

Development Notes
=================
• All panels follow the pattern: pub fn render(f: &mut Frame, app: &App, area: Rect)
• Focus management via FocusPanel enum
• Async operations use Tokio spawn_blocking for CPU-bound work
• Image cache uses Arc<Mutex<>> for thread-safe sharing
• Audit log auto-prunes to 1000 entries
• Virtual scrolling prevents memory issues with large icon sets
• No unsafe code used anywhere
• Proper error handling with anyhow::Result throughout
